## 1. 为什么删 pyecharts（硬论证）

1. 它的长处（渲染/主题/HTML）全是你架构里不需要的；短处（体积、API 漂移、`JsCode`）全由你承担。
2. 体积进 sidecar：DEVLOG [18] 测出打包版起 worker 0.7–0.9s，pyecharts 带 jinja2 等传递依赖只会恶化。
3. 模型不熟它的 v1/v2 API —— 等于给自己加一个"写法兼容层"要维护。
4. `JsCode` 是纯 option dict 里不存在的通道。

**替代**：`chart(kind, df, ...)` —— 输入 DataFrame 与列名，输出 ECharts option dict。零依赖、可单测、API 由你定死。

---

## 2. 目标架构：三层

```
[沙箱 worker]
   模型代码：chart(kind, df, x=列, y=列, series=分组列, title=...)   ← 只选图型/列/标题
   build_option()：从 df 生成 data 层 + 默认 style 层 → option dict（纯函数）
   chart()：调 build_option + 记入 worker 槽位 + 返回 None
   → 记 chart_error（不抛）→ wire.py 回传
[校验层]（worker 内，exec 之后）
   option 白名单校验（键、类型、字符串清洗）
[后端接口]
   exec 事件 / 会话接口带 chart_option（SSE）
[前端 ECharts]
   套主题 + 开关（0 token）+ 层 1 面板 DIY（0 token）
   层 2 一句话改（1 次小 LLM 调用，v2）
```

**核心不变量：data 层由 builder 从 df 生成，模型够不着；style 层由前端套。**

## 3. option 格式规范：data 层 / style 层

### 3.1 data 层（v1 由 builder 独占产出，模型零输入）

```json
{
  "xAxis": { "data": ["Q1","Q2","Q3","Q4"] },
  "series": [ { "name": "销售额", "type": "bar", "data": [120,135,98,160] } ]
}
```

- **v1 不产出 `dataset`**：只出 `series[].data` + `xAxis.data` → `dataset.source` 绕过面**从源头不存在**。
- 层 1 前端只读不改（除专列出的样式键）；层 2 模型输入直接丢弃。

### 3.2 style 层

| 类别 | 键 | 层 1 | 层 2（模型） |
|---|---|---|---|
| 调色 | `color[]`、`series[].itemStyle.color` | ✅ | ✅ |
| 文字 | `textStyle`、`title.textStyle`、`series[].label` | ✅ | ✅ |
| 图例 | `legend.show` / `orient` / `top` | ✅ | ✅ |
| 图型开关 | `series[].smooth` / `stack` / `areaStyle` | ✅ | ✅ |
| 柱形 | `itemStyle.borderRadius` | ✅ | ✅ |
| **轴范围** | `yAxis.min` / `yAxis.max` | ✅ **仅用户** | ❌ |
| **分段** | `visualMap.pieces` | ✅ **仅用户** | ❌ |
| **排序** | （前端对 data 排序） | ✅ 仅用户 | ❌ |

> `yAxis.min/max`、`visualMap.pieces`、排序**不属于纯样式**——会改变图传达的信息。**层 2 白名单必须排除这三类。**

## 4. 安全模型

### 4.1 风险面（对齐后）

title / legend / axisLabel **画在 canvas 上，不进 DOM**。真正进 DOM 的通道：

1. **HTML 模式的 tooltip**（`tooltip.renderMode:'html'`，默认）
2. **`toolbox.feature.dataView`**（HTML 面板）
3. **`aria`**（开启时生成 DOM 描述）
4. **`title.link` / `title.sublink`** —— 创建**真实的 `<a>` DOM 节点**；href 为 `javascript:` 或带事件时点击可执行
5. **`graphic`**（可含 HTML 类型元素）

### 4.2 对策（已采纳，不再讨论）

- **前端统一 `tooltip.renderMode:'richText'`** —— HTML 通道结构性消失，优于转义。
- **`toolbox.feature.dataView` 不开。**
- **`aria` 保持默认关闭**（`aria.enabled:false`）。
- **白名单禁 `title.link` / `title.sublink` / `graphic`。**
- 字符串仍做**长度上限 + 控制字符清洗**，作为纵深防御。

### 4.3 待验证：注入实测（按完整清单逐字段）

第 5 步用注入字符串实测，断言 `renderMode:'richText'` 下不产生可执行 DOM：

```
title.text / title.link / title.sublink
series[].name / series[].label.formatter
xAxis.data[]（类目名）
legend.formatter
tooltip.formatter（字符串模板 与 白名单值）
aria.label / aria.description
```

结果写进 `docs/THREAT_MODEL.md`。

## 5. 层 1 / 层 2 + B44 脱钩

| | 层 1 面板直改 | 层 2 一句话改 |
|---|---|---|
| 参与方 | 纯前端 | 前端 → LLM → 前端 |
| token | 0 | 1 次小调用 |
| 攻击面 | 无新增 | **新增** |
| 建议 | 先做，主菜 | v2，丢弃式白名单 |

### 5.1 层 2 校验：丢弃式 > 拒绝式

v1 的"比对 `series[].data`"可用 `dataset.source` / `xAxis.data` / `yAxis.min-max` / `visualMap.pieces` 绕过，且结构重组会误拒。

**正解（"改之前限定"）**：option 划 data / style 两层；层 2 **只接受对 style 白名单键的 patch**；data 层**根本不接受模型输入**（合并前丢弃）。

### 5.2 B44 实现脱钩 + 返回值堵法

**脱钩现状核验**（`sandbox_worker.py`）：

```
:222-225   try: exec(code)          except: out["error"]=...      ← exec 内，模型代码
:226        if out["error"] is None:
:227-231      try: if plt.get_fignums(): _orig_savefig(...)
              except Exception: pass       ← exec 后图保存异常已被吞，不影响 result ✅
:232-235      try: out["result"] = wire.encode(...)
              except: out["error"] = "结果无法回传："...           ← result 自身的失败，合理
:237        out["chart"] = os.path.exists(chart_path)
```

**分界（已采纳）**：exec **之外**的图表处理**已脱钩**（`:227-231`）；exec **之内**（模型代码抛异常）**不修** —— result 是否终值无法判断。

**要修的是 exec 之内 `chart()` 抛异常**：`chart()` 一旦抛 → 整段 exec 失败 → B44 重现。方案：

1. **`chart()` 内部不抛异常**：任何异常记进 `chart_error` 后返回。
2. **白名单校验放 exec 之后**，worker 自己做，与 `wire.encode(result)` 分开 try。
3. **`out` 分开记 `error`（只管 result）与 `chart_error`**。

**返回值堵法 —— 采纳 H 的方案（比深拷贝更硬）** `[v3]`：
`chart()` **在调用那一刻**就把 option 记进 worker 自己的槽位，然后**返回 `None`**。模型拿不到对象，无从修改 —— 从"约定/防御"变成"结构上不可能"。多调用规则：按调用顺序保留，**最多 4 张**，超出记 `chart_error`。

**纯函数与副作用分离** `[v3 补充]`：`build_option(kind, df, ...)` 是**纯函数**（返回 option dict，可单测）；`chart(...)` 是**薄包装**（调 builder + 记槽位 + 返回 None，有副作用）。**可单测的是 builder，不是 chart。**

## 6. 预设、开关与 builder

### 6.1 主题

- ECharts 内置：`macarons` / `shine` / `roma` / `vintage` / `dark` / `infographic`
- 自研 3–4 套：**汇报风** / **极简** / **深色** / **商务蓝**
- `echarts.registerTheme(name, obj)`，前端切换即重绘，**不重新跑代码**

### 6.2 通用开关（0 token）

数值标签 / 图例位置 / 横向↔竖向 / 堆叠 / 平滑曲线 / 渐变填充 / 圆角柱 / 排序 / 平均线与极值标注 / `dataZoom`。

### 6.3 换图型（判据落成条件）

| 变换 | 是否可换 | 条件 |
|---|---|---|
| 柱 ↔ 折线 ↔ 面积 | ✅ | **category 轴 + 单个数值 series** |
| 饼 / 环形 / 玫瑰 | ⚠️ | 需**单维聚合**（category + 单数值），多 series 不可换 |
| 散点 | ⚠️ | 需**两个数值列**（x/y） |
| 热力 / 桑基 | ❌ | 数据类型不兼容 |

### 6.4 v1 builder 支持的图型与签名 `[v3 扩展]`

**先做 `bar` / `line` / `area` / `pie` / `scatter`**，覆盖不到时**退回 matplotlib PNG**。

**签名（支持多系列）**：

```python
build_option(kind, df, *, x=None, y=None, series=None, title=None)
```

- **`y` 可为一列名，或列名列表（宽表：多列 = 多系列）**
- **`series=` 传分组列（长表：一列分组 = 多系列）**
- **`y` 与 `series` 不能同时给**
- **排序、Top-N 由 pandas 先做好，builder 不提供这些参数**（保持纯函数）
- 每张图**最多 5000 点**，超出截断 + 打 `truncated` 标记
- **NaN → `null`；时间列 → ISO 字符串**

> **JSON 序列化的硬要求** `[v3 补充]`：`json.dump` 默认 `allow_nan=True` 会写出 `NaN`/`Infinity` —— **这是非法 JSON，前端 `JSON.parse` 直接抛错**。不只是"美观"，是**必须**。同时 `numpy.int64/float64` 与 `pandas.Timestamp` 都不是原生 JSON 类型，builder 要一并转。

### 6.5 离线覆盖率怎么量 `[v3 新增]`

历史画图代码都是 matplotlib 写的。**分两步**：

**第一步（优先）：静态分类。** 扫 `docs/eval` 里所有报告的 `code`，按调用归类：

```
bar / barh / plot(kind=) / pie / scatter / hist / twinx / subplots / 堆叠
```

> **扫描正则要覆盖三种写法**：`plt.bar` / `ax.bar` / `df.plot(kind='bar')` —— 模型写法不统一，只匹配一种会漏。

**只有静态判断不了的那部分才重放。** 这样"从 Figure 反解"只剩**离线测量工具**这一个用途，**不进产品**。

**`hist` 与双轴（`twinx`）单列统计** —— 这是五类图型最可能覆盖不到的地方。

> **样本量提醒**：`docs/eval` 里的画图代码样本很小（几十量级），结论只作**方向性判断**，不作为精确覆盖率。

## 8. 阈值与判据

### 8.1 B44 必须在第 1 步定死

**图失败不得连累 result**（详见 §5.2）。

### 8.2 回归门槛

**单表 ≥ 14/15、多表 ≥ 9/10（`[30]`：`[25]` 已把多表上界从 8/10 修正），并注明"m10 波动不计入回归"。**

证据（v1 时没有）：`m10` 在 `gate_20261013_151425_react.json`（15:14，`cf277ed`）**auto=True**、在 `gate_20261013_153017_react.json`（15:30，`cdaf0f6`）**auto=False** —— 同日下午相隔 16 分钟、同模型同题、一次对一次错。它是波动型的 ⑥，**绘图改动修不了它**。

### 8.3 图表自身判据 `[v3 重写：expect_chart 路线作废]`

**v2 的 `expect_chart` 路线走不通 —— 事实核过**：

- 闸门 `questions.py` 里"**图**"出现 **0** 次 —— 25 题没有一题要求画图，标完 `expect_chart` 分母是 **0**。
- 改题面会动 `questions_sha256` —— **为了测图表去动一份已冻结的题集，不值得**。
- 实际情况是**模型自己决定画不画**：昨天两轮都是 25 题里 **5 题**画了图（`s10`/`s11`/`m01`/`m03` 两次都画，第五题一次 `m08`、一次 `m10`）。

**采纳 H 的替代方案**：

- **分母** = 这一轮"模型画了图的题"（代码里调了 `chart()` 或 `plt`）
- **分子** = "产出了合格的 `chart_option` 的题"
- 分母只有 5 左右，90% 没法精确表达 → **写成计数门槛**：**每轮画图的题里，至多 1 题没有合格的 `chart_option`**
- **并且：自造评测集里 3 道 `has_chart=True` 的题全部产出**（`app/eval/cases.py:50,253,266`）
- **不改题面，不动 `questions_sha256`**

**`[v3 补充] 我加一条区分 —— `plt` 画的图没有 `chart_option`，别混进同一分母：**

v1 builder-only 下，`plt` 那条路（五类以外）产出的是 **PNG，不是 `chart_option`**。若把 `plt` 题的图算进"chart_option 通过率"分母，它们**必然**判失败，会假性拉低。所以要**分两条独立记**：

| 判据 | 分母 | 分子 | 门槛 |
|---|---|---|---|
| **出图率**（冒烟：图有没有出来） | 调了 `chart()` **或** `plt` 的题 | 产出了**图**（`chart_option` **或** png）的题 | 每轮至多 1 题无图 |
| **chart_option 链路** | 调了 `chart()` 的题 | 产出合格 `chart_option` 的题 | 全部合格（或 `chart_error` 有明确原因） |

**注明**：这条判据分母很小（约 5），只是"**图做出来了**"的**冒烟测试**。**真正的图表评测留给阶段 7 的新留出集** —— 到时候专门放几道要求画图的题。

4. **builder 报错策略**：列名不存在 / 类型不符时记 `chart_error`，**不画空图**。

## 12. 开关 × 产出键（`[v4]` 新增；v2 层 2 patch 白名单的输入）

**这张表解决的是一个死角**：v1 前端**不**校验白名单（THREAT_MODEL §2.3 —— 白名单只校验 builder 输出，前端产物永不回验），所以前端的开关可以写任何键。但如果 v1 的开关写了 `markLine`、而 v2 层 2 的后端白名单不收它，就会出现"**面板能改、一句话改不了**"。下面"前端实际写出"一列是 F3 第五步落地后开关真正写出的路径（`ui/web/src/charts/switches.ts` 的 `FRONTEND_KEYS`，`switches.test.ts` 读本表比对，多写漏写都红）；"v1 `_ALLOWED`"一列是 `app/tools/charts.py` 的 `_ALLOWED` 现状（`✅`=已允许），第四列是 v2 必须补的。

1. v1 前端的清理列表做成常量，直接**镜像** `BANNED_KEYS`（只有 `renderMode` 从"禁"改成"强制设值"），并加一条测试断言它与 Python 侧一致 —— 否则两边各维护一份，必然漂移。
