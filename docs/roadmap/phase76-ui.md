# 阶段 7.6：页面改造（方案）

> 编号：排在 7.5 之后。方案先评审，实施排在 7.5 第 2 步（Excel 输入、导出）之后。页面依赖的是第 2 步的数据集剖析和导出，以及已有的 warnings 和 grounding 数据，不依赖第 1 步的回放。
> 参照：Folio（github.com/helsome/folio）首页。**只借它的结构，不借它的内容。**

本文件只写决策和验收，任务进 BACKLOG「阶段 7.5」分区。

## 0. 结论

页面简陋，问题不在图，而在承载图的界面。缺的是三样东西，没有一样能靠调 CSS 补上：

| 缺口 | 现状（代码证据） | 要变成 |
|---|---|---|
| 产品叙事 | 首页是一张上传卡，写着「拖入文件到此处 / CSV · 可多选」（`Shell.tsx:420-428`） | 回答「这份数据是什么、我能问什么」 |
| 数据理解 | 侧栏的数据源只显示文件名和表名 | 数据资产卡：表数、行数、列数、时间范围、缺失 |
| 可信度可视化 | 信号已经在展示：`turn.ts:165` `partialSignals` 把 warnings 和 `unverified_numbers` 合并成一条黄条（`TurnView.tsx:167`）。问题是三类信号挤在一行（截断/提示、未核实数字），读不出哪类、哪几个 | 拆开：校验徽章单独承载未核实数字，点开列出具体数字；warnings 保留为提示条 |

**观感差距等于功能数差距。** Folio 的首页聚合了六个功能的状态，datachat 只有一个功能的输入框。目标不是凑出六个功能，而是把这一个功能讲清楚：数据是什么、结论是什么、凭什么可信、下一步能做什么。

## 1. 问题归属：图层的不进本方案

逐条核对之后，截图里的问题有一半属于图表本身，改页面解决不了。这一类归 M13 的图表规则，单独成批（见 §5），**不计入本方案的验收**。

| 问题 | 归属 | 修法 |
|---|---|---|
| 图标题里的「图3」「图4」编号不连续 | 模型自己在 matplotlib 里写的标题 | 规则：禁止在 title 里写「图N」；编号在导出报告时由后端统一加 |
| 堆叠柱没有图例 | 图表规则 | 多系列的图必须有图例 |
| 双轴图柱子绿色、折线红色 | 图表规则 | 红色只用于负值或警示 |
| 图 1 顶部的「14」被切掉 | PNG 自身的边距 | `sandbox_worker.py` 的 `_redirect_savefig` 强制 `bbox_inches="tight"`。不动 prompt，但这是**字节契约变更**：每张 PNG 的字节都会变，要重取 chart_fixtures 和视觉基线，单独走变更流程 |
| 「静态图（由 matplotlib 生成），可右键另存为」 | 界面文案（`TurnView.tsx:233`） | 归本方案：换成「导出 PNG」按钮，复用 `app/server/exports.py` |

双轴图、箱线图这类只能走 plt，因为 builder 只有五种图型（`plotting.py:38`）。长期的修法是给 builder 加一个 `bar_line` 双轴图型，让配色、图例、编号回到前端主题统一管理，这比教模型写对 plt 更稳。这件事归 M13。

| 项 | 内容 | 验收 |

| U1 工艺层 | 字阶：现在根字号 13，正文 12，辅助文字有 9.5、10.5、11、11.5、12.5 五档，档与档之间差太小（`styles.css`）。收成三级：标题 20/22，正文 13，辅助 12。卡片 padding 统一为 20–24，间距统一为 12–16。主题下拉移到图表工具栏 | 新增 vitest：`styles.css` 里的 `font-size` 只允许出现在字阶表里的值。视觉基线用 CI x64 重取 |

## 3. 不做

- 不照搬 Folio 的卡片内容。「总资产 US$109,210」在 datachat 里没有对应的东西，硬做出来就是假数据。datachat 里对应的是「这份数据长什么样」。
- 不加阴影、渐变、毛玻璃。Folio 的高级感来自排版、留白和单色，卡片只有 1px 边框。
- 不加点了没反应的入口。每个按钮必须通向一个真实功能。

## 4. 保留并推广

- 设置页的「已设置（来源：系统凭据）」：状态加来源，一句话说清。数据资产卡和校验徽章都沿用这个写法。
- 数据集上的「使用中」标记。
- 口径的导入和导出（`NotesSection.tsx:78`）已经存在。这是「团队共享知识、不共享运行时」的现成载体，U2 的数据资产卡上要给它一个入口。

## 5. 图表规则小批（归 M13，单独一个 PR）

1. `_redirect_savefig` 强制 `bbox_inches="tight"`。按**字节契约变更**处理：所有 PNG 字节改变，同一个 PR 里重取 chart_fixtures 和视觉基线（CI x64 actual），PR 描述写明。
2. CHART_GUIDE 的 plt 段补三条：禁止在 title 写「图N」；多系列必须有图例；红色只表示负值或警示。按 phase75 §3，这属于作用域限定在图表的规则，回归可以只跑图表题的子集；子集入口补上之前，先跑全量。
3. builder 加 `bar_line` 双轴图型，另起评估。

## 6. 已定（S 2026-11-19）

1. 会话标题不调模型：本地规则，jieba 取第一个名词短语加指标词，取不到就截断 12 字。理由：多一次调用就多一次延迟和失败点，收益只是列表好看。
2. 顺序：图表小批（按字节契约变更走）→ U1 → U2 → U3 → U4。U1 只改 token 表，不动组件结构，以免和 U2/U3 冲突。
3. 截图（charts / settings / folio 三张）由 S 转交；留白一条按设置页处理。
