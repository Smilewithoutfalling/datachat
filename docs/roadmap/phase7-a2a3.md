## A2 结果合理性校验

**做法**：代码执行成功之后，用 `app/tools/sanity.py::result_issue` 检查结果，命中任意一项就送 reviewer 再看一遍，**只给一次机会**：

| 形态 | 说明 |
|---|---|
| 空结果 | 0 行的 DataFrame / Series，或 0 列的 DataFrame。最常见的原因是筛选值和实际写法对不上 |
| 全是空值 | 标量 NaN，或者 Series / DataFrame 的值全部是 NaN |
| 无穷大 | 数值里有 inf，通常是除以了 0 |

结果是 dict 时逐个值检查。字符串（包括拒答）不检查。

**已定规则**
1. 可疑不等于报错：不写进 `error`，而是另记 `state.sanity_issue`，路由（`graph._route_after_exec`）把它和报错同样送进 reviewer。重试次数用完或预算到了时，结果**照常**交给 summarizer，不会因为「可疑」被丢掉。
2. 只给一次：`state.sanity_retried` 置位后不再检查。reviewer 原样交回同一份代码，第二次的结果就照常放行。
3. reviewer 收到的「错误信息」是：可疑点 + 检查清单（取值写法、分母、列）+「确认结果就是对的，原样输出原代码即可」。
4. 不做：占比之和偏离 100%（子集占比本来就不到 100%）、数量级突变（没有参照值）、计数为 0（「已取消的有几单」答 0 可能是对的）。
5. `AnalysisResult.sanity_issue` 记录第一次触发时的说明，方便看 trace 和评测归因。

**离线误报检查**：用全部 202 题、217 份 gold 结果（含 alt）跑一遍 `result_issue`，**命中 0 份**。

## A3 枚举值召回

**做法**：`app/tools/value_hints.py`。把问题分词（jieba，词长 ≥ 2，并且至少含一个字母或汉字），和每个文本列的不同取值（列的不同取值数 ≤ 2000）做匹配。匹配前先归一化：NFKC、去掉所有空白、统一小写。算命中的情况：两边相等，或者一方包含另一方、并且短的一方至少占长的一半（「华东」对「华东区」算命中，「商品」对「数码商品01」不算）。命中的结果附在字段说明后面，用数据分隔块包起来。

**只在能补上新信息时出提示**：
- 模糊命中（问题里的写法和实际取值不完全一样）；
- 精确命中，但这个取值在样例行里看不到；
- 同一个词在一列里对上了好几种写法（「已完成」「已完成  」「 已完成」），这种情况都列出来，哪怕都在样例里。

没有提示时 prompt 逐字节不变。P8 / state 哈希不受影响，`tests/test_memory_p8.py` 没有改动。

**措辞**：写的是「仅供对照写法；该不该用来筛选，按题意判断」，不写「必须按这个筛选」。因为离线统计里有 `biz_007` / `biz_015`：问题里的「退款」命中了 `orders.status` 的「已退款」，但这两题的口径都是按退款表算，硬性措辞会把模型带偏。

**出境合同（硬约束）**：`app/eval/egress.py` 第 3 条规定任一文本列的取值出境不超过 3 个。每一列先数「样例行 + 问题原文」里已经出现的取值，提示只能补到这一列总共 3 个为止。所以样例行已经露出 3 个不同取值的列，A3 一个都不加，这是这一步最大的限制。要放宽，就得改出境合同，这一点由 S 决定，本 PR 不动。

**离线命中统计**（202 题共 256 轮问题）：18 轮有提示，全部在 `biz_*`。主要是「已完成」的空格变体（题面本来就提示了「状态值前后可能有空格」），`biz_014` 的 Gold/gold，以及 `biz_007` / `biz_015` 的「退款」→「已退款」（见上文措辞）。`sales`、`orders`、`emp`、`inv` 这些单表题都是 0 条：样例行里能看到，或者问题原文就写对了。
