# canary：十条探针，探模型权重有没有换

> 生成/维护方式：清单在 `app/eval/canary.py`，跑法见下。**本文件里的数字是实测读数，
> 换题单就整段作废，别在旧数字上接着算。**

## 它回答什么，不回答什么

| 问题 | 能不能回答 |
|---|---|
| 代码没动、题没动、模型名也没动，读数变了——是不是权重换了？ | **能**。这就是它存在的唯一理由 |
| 这批改动让模型变强了没？ | 不能。十条是挑出来的稳定题，不构成能力抽样 |
| 为什么某题翻了？ | 不能。它只报警，归因要自己去看原始输出 |

背景：指纹体系里 `fingerprints.model` 记的只是名字 `Qwen3.5-397B-A17B`，网关后面换成哪个
快照，报告一个字符都不变。eval-v0 三次运行 `attempts` 从 22 涨到 37/38/37、prompt 逐字
未变，只能归到模型侧，但拿不出证据。这是台账缺口 3。

## 三条硬门槛

1. **必须单轮。** 多轮一拍上记忆模式（`off` 回灌 messages / `state` 渲染成数据块），
   翻转就分不清是权重变了还是编排变了。探针只能有一个变量。
2. **必须是标量答案。** `int` / `float` / `str` / `bool`。Series 与 DataFrame 的比对躲不开
   索引写成日期还是日期区间、行列谁先谁后、标签是周起始还是周结束——那些抖动属于判分器。
   这条是踩出来的，见下节。
3. **题面不能留解释空间。** 歧义类靠 `alt_ground_truths` 容错，判定边界本身在晃；
   `status` 三态下「金额合计」这类留白同理（缺口 6）。

守门由 `tests/test_canary.py` 做，其中 `test_canary_ground_truth_returns_a_scalar` 会真跑
十条 gold 检查返回类型。加题时漏了这一条，测试会拦。

## 跑法

```bash
python run_eval.py --canary --agent react --repeat 3      # 跑探针
python scripts/eval/canary.py "outputs/eval_react_canary_*.json"   # 与冻结基线比
```

- `--agent react` 是当前基线用的 agent。换 agent 会让 `batch_key` 不同，读数不可比。
- `--canary` 与 `--case` 互斥，同时给直接报错退出，不猜你想跑哪批。
- 报告自动标 `canary: true` 与 `canary_sha12`，台账据此单独成表，**不进全量趋势**。
- `scripts/eval/canary.py` 只读报告、不跑模型。退出码：0 干净或合同类 / 1 漂移 / 2 不可比或
  基线过期。加 `--out drift.json` 存一份机器可读结果（`.github/workflows/drift.yml` 就是这么用的）。
- 重立基线：`python scripts/eval/canary.py "<那批报告>" --init --force`。**它会拒绝静默覆盖**，
  没有 `--force` 就返回 2 —— 自动更新基线等于让哨兵自己闭嘴。

offline 自检（不调模型，只验证 gold 与判分自洽）：

```bash
python run_eval.py --canary --oracle
```

## 判读规则

前提：**`canary_sha12` 与 `judge_sha12` 都必须和基线一致**，否则不是漂移，是换了卷子
（`incomparable`）或换了尺子（`stale_baseline`）。这两种由 `scripts/eval/canary.py` 直接判，
退出码 2，动作是「改题单」或「重立基线」，不是「查权重」。

`judge_sha12` 只覆盖**判分器**（`app/eval/comparator.py`、`app/eval/negative.py`）与
**数据表内容**（`DATASETS` 全部 CSV + 各表字典），不覆盖 `app/**/*.py` 全量。
旧判据是 `code_sha12` 全同，2026-11-09 收窄 —— 它含 prompt / 工具 / 记忆编排，
一周改好几次，要求它全同等于让哨兵永远停在"该重立基线"（10 题 × 6 跑），
而没人会为改一行 prompt 重跑六轮，于是它静默失效。失效方式不是报错，是被无视。
产品代码改过时 `code_sha12` 仍会写进 reason 提示归因方向，但**不阻断比对**。

基线（2026-11-04 09:40，6 跑 / 60 题次，`docs/eval/canary/baseline.json`）：

| 项 | 值 |
|---|---|
| 判对数 | 9 / 10 / 10 / 9 / 10 / 10 |
| 逐题翻转 | 2（`ord_013`、`ord_017`，各掉一轮） |
| 两次掉题的形态 | **都是「答对了没交卷」**：`no_assign`，答案正文与 gold 逐字相同（660 / 0.3665） |
| usage 比例 | in 94.4% / out 5.6%；`cache_read` / `reasoning` 网关恒不回（None） |
| 指纹 | `canary_sha12 = 592b9f3baa7e`、`code_sha12 = 4b58e8b9fd80`、`judge_sha12` **缺** |

> ⚠️ **这份基线已经不可用（2026-11-09 起）。** 当前 `code_sha12 = a2ca51b11273`
> （C-001 改字典、C-002 改题面），且基线里**没有 `judge_sha12` 字段**。
> `scripts/eval/canary.py` 会判 `stale_baseline`（退出码 2）并提示重立 —— 这是正确行为。
> 重立命令：`python scripts/eval/canary.py "<那批报告>" --init --force`，成本 10 题 × 6 跑
> ≈ 26 万 tokens_in / 1.6 万 tokens_out（按本基线自己记的 `usage_total`）。
> 重立之前，漂移哨兵处于失效状态；打开 `DATACHAT_CANARY_ENABLED` 只会得到退出码 2。

判读按**机制**分，不按条数分：

| 现象 | 结论 | 退出码 | 动作 |
|---|---|---|---|
| 掉题里有**算错**（不是 `no_assign`，或答案里找不到 gold） | `drift` | 1 | 查权重 / 数据 / 网关 |
| 掉题**全是**「算对没交卷」 | `contract` | 0 | 查输出契约，别查权重 |
| 没掉题，但 usage 比例移动 >20% 或字段覆盖变了 | `drift` | 1 | 网关回包变了 |
| 以上都不是 | `clean` | 0 | — |

**为什么不是「掉 1 题就报漂移」。** 规格原文写的是「accuracy 掉 ≥1 题即 drift」。11-04 实测
60 个题次掉 2 次（3.3%），**两次都是答对没赋值**，而且换着题出（不是某一道题的问题）。
按条数判，这 6 跑里有 2 跑会响（1/3），而它们都不是权重问题 —— 一周一次的哨兵照这个频率
响，三个月后就没人看了。所以「算错」一次就报，「没交卷」单独成档：它是真实的输出契约
问题（该修 Agent 的提示与契约），但它**不指向权重**，10-30 排除 `ord_004` 用的就是这一条。

**`answer_sha12` 只记录，不判据。** 同一批 5 跑里十条答案的文本**全都不同**
（`answer_varied = 10/10`，temperature 0 也如此），拿它当漂移判据等于每次都报警。
它的用处只有一个：判错时区分「文本没变但判定变了」（尺子的事）和「文本变了」（模型的事）。

## 11-04 重立基线：旧锚点为什么作废，2/60 又是什么

**旧基线为什么不能再裁定今天。** 10-30 那份是 `code_sha12 = 7562832e9e11` 下的读数。
之后判分器改过两次（[114] 时间归一、[116] 规则 16），A 组文件一动，`code_sha12` 变成
`4b58e8b9fd80` —— 按本文件自己的规矩，旧基线从此只说明"那天是那样"。拿它对着今天的读数
跑，`scripts/eval/canary.py` 给的是 `stale_baseline`（退出码 2），并把观察到的差异附在
原因后面。这才是工具该有的样子：不下结论，但不隐瞒。

**新基线没挑干净的。** 6 跑（两批各 3 跑）全进了 `baseline.json`，`flips = 2` 照写。
剔除掉题的那两轮会得到一份 `10/10 × 6` 的漂亮基线，但那是拿最好看的样本当锚点 ——
[113] 的 3 条假阴性就是这么来的。

**两次掉题的原始输出**（逐条查过，不是"看起来像"）：

| 题 | 判分器取到的值 | 答案正文 | 模型写的代码 |
|---|---|---|---|
| `ord_013`（第一批 run1） | `None`，`result_missing=no_assign` | 「共 **660 笔**」—— 与 gold 660 一致 | 只有 `print(d['discount'].value_counts(...))` |
| `ord_017`（第二批 run1） | `None`，`result_missing=no_assign` | 「皮尔逊相关系数为 **0.3665**」—— 与 gold 0.3665 一致 | 只有 `print(round(d['qty'].corr(d['pay_amount']), 4))` |

**不同批次、不同题，机制一模一样：算对了，忘了交卷。** 这是输出契约的履约率（60 个题次里
2 次，3.3%），不是能力问题，也不指向网关换模型。

**它顺带解释了 10-30 的「50 次判定零翻转」。** 那 5 跑确实全对，但按 3.3% 的题次率，
50 次里一次不掉并非不可能（约 0.19）。所以那不是"模型更稳"的证据，只是样本小 ——
当时的结论没错，支撑比看上去薄。

## 第一版作废了：一次代价不小的教训

初版（2026-10-30 12:23）按「台账 `## 翻转题` 里出现过、且单轮、非歧义」挑，选出
`ord_004` / `ord_003` / `ord_013` / `inv_007` / `corr_003` / `corr_001` / `ts_007` / `inv_016` /
`inv_021` / `emp_022`。3 跑结果 100% / 80% / 80%，翻 3 题。逐条查原始输出，**没有一条是算错**：

| 题 | 表面现象 | 真实原因 |
|---|---|---|
| `inv_016` | 判错 | 数值逐项相同（1070 / 2258 / 2108…），只是索引写法不同：run1 给周起始 `02-26`、run2 给区间串 `02-26~03-03`、gold 是周结束 `2024-03-03`。判分器只认前两种 |
| `ord_004` | 判错 | 三跑答案都是 832.54（正确），run2/run3 只写 `print(...)`、没给 `result` 赋值，判分取到空值 |
| `emp_022` | 判错 | 「离职的主要原因」本来就允许答成司龄 / 部门离职率分布，run3 就那么答了 |

三条各有各的问题，共同点是**都不指向权重**。原因是我当时按「历史上翻过转」选题，却没查
它当初为什么翻——台账里明明写着「eval-v2 的 9 题翻转逐条查下来，2 题是尺子的问题」。

换成标量题后，同样 10 条跑 5 次：100% × 5，翻转 0。

两条教训：

1. **「翻过转」不是敏感度的证据，是「该查一下为什么」的信号。** 挑稳定探针要看它为什么稳，
   不是看它曾经不稳。
2. **判分器能力 ≠ 模型能力。** Series/DataFrame 的比对永远带着表示法约定，把这类题放进
   探针，等于用判分器的容错度去测模型。

作废的三份报告留在 `outputs/_superseded/`，不删，但别拿那些数字当基准。

## 已知局限

1. **只锁十条。** 权重漂移如果在别的能力面上（比如长链推理），这十条可能全过。
   它是**探针不是体检**：探针绿了只说明「这十个点没动」。
2. ~~**依赖 `code_sha12` 不变。**~~ **已解除（2026-11-09）。** 判据改成 `judge_sha12`
   （判分器 + 数据表），产品代码改动不再阻断比对 —— 代价是"改了 prompt 导致掉题"会被
   判成 `drift`，reason 里会附 `code_sha12` 差异提示先归因到自己的改动。
   日常回归仍然别用 canary：它是探针不是回归套件。
3. **`canary_sha12` 覆盖题面与判分字段，不覆盖数据文件** —— 数据这部分由 `judge_sha12`
   补上了（2026-11-09）。两个指纹合起来才是完整的"同一件事"：题面 + 判分器 + 数据表。
   仍不覆盖的是**执行器**（`runner.py` 怎么取 `result`）和**记忆编排**，它们变了会被归到
   模型侧 —— 那是可接受的误报方向（宁可让你去查，而不是让哨兵闭嘴）。
4. **拒答题只有 2 条。** 拒答边界是最容易随权重游移的地方，两条偏少；等有更死板的拒答题
   再加。目前 `inv_021`（销售额）与 `emp_022`（离职原因）都因为允许近似回答而没进清单。
5. **逐题读数不归档。** `outputs/` 在 `.gitignore` 里，台账只留一行汇总（正确率 + 翻转数），
   每跑哪题对哪题错不入库。真出现漂移时，要保住那次的 `outputs/eval_react_canary_*.json`
   再分析，别清空。
6. **基线里掉过的那两题，从此不参与"掉题"判定。** `ord_013` / `ord_017` 在基线的 6 跑里各错
   一轮，所以 `all(base.passes)` 为假，判据自动跳过它们（用晃的尺子量晃的东西没有意义）。
   代价是哨兵实际只盯 8 条。要恢复成 10 条，得先证明这两题能稳定（比如再跑 5 轮全对），
   再重立基线 —— 别手改 `passes`。
7. **同一题同一次判定的重复率约 3.3%（`no_assign` 类）。** 这是模型侧的履约波动，
   temperature 0 也照出。它不影响 `clean` / `contract` 的判定（已经分开），但会让
   `flips` 长期不是 0 —— 看到 `flips = 2` 先看形态，再谈结论。
